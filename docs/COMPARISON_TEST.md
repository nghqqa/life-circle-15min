# 真实社区对比测试报告

> 对应赛题交付要求「针对特定社区的真实对比测试报告」。
> 测试时间：2026-10-10 ｜ 测试环境：Windows 11 · Chrome（内嵌浏览器视口 1600×950）· 本地部署（localhost:8807）
> 数据通道：浏览器端通道（GL JS API：LocalSearch 检索 / Geocoder 编码 / WalkingRoute 算路）。
> 服务端通道（批量算路 routematrix）在测试窗口处于 AK IP 白名单传播期，恢复后需补测一组
> （历史窗口内的一次服务端通道完整运行样本已收录 §3.4）。

## 1. 测试对象

| 项 | 样例 A（主样例） | 样例 B（对照样例） |
| --- | --- | --- |
| 社区 | 江西师范大学数字产业学院（上饶市高铁经济试验区） | 上饶市信州区中心广场（老城核心） |
| 中心点坐标（BD-09） | 28.50509, 118.02389 | 地理编码获得（GL Geocoder） |
| 中心点来源 | 引擎内置地理编码（GL Geocoder，城市限定上饶市） | 地址输入"上饶市信州区中心广场"→ 地理编码 |
| 选点理由 | 新建校区，规划配套尚未成熟，预期存在真实服务盲区 | 成熟城区，预期各类设施齐备，用于验证系统区分度 |
| 测试日期 | 2026-10-10 | 2026-10-10 |

## 2. 实测步骤

1. `npm run dev`（本地为 `PORT=8807 npm start` + 静态托管）启动应用；
2. 输入样例地址定位 → 选择人群 → 点击「开始体检」；
3. 记录「运行日志」页签中每步通道、耗时、探针成功率；
4. 导出报告并核对：分类明细、灰色斑块、规划建议、国标清单；
5. 切换「老年人」视角重复，记录可达范围收缩与结论变化；
6. 与人工常识核对：样例 A 为在建新校区（周边为工业区与信江），样例 B 为上饶老城核心（步行可达三条商业街）。

### 3.3 人群差异（样例 A）

- 老年人视角（52m/min）下 15 分钟可达半径收缩约 **35%**（1200m → 约 780m 直线）；
- 可达圈内"三件套全无"的居住权重占比由 55% 升至 **100%**——成人尚可勉强走到最近的菜市场/小学，
  老年人则在 15 分钟内完全无法触及任何核心设施；
- 结论：对同一社区，**老年人群体的生活圈达标情况显著更差**，验证了人群差异化体检的必要性。

### 3.4 通道与性能对比

| 指标 | 服务端通道（历史样本） | 浏览器端通道（本次口径） |
| --- | --- | --- |
| 等时圈采样 | 48 向批量 routematrix | 16 向 GL WalkingRoute 逐向 |
| 路网采样耗时 | ≈2.1s | 2.7s |
| POI 检索 | place v2（REST） | LocalSearch（GL SDK） |
| 全流程耗时 | **11s** | 17-28s |
| 单次分析配额 | 服务端 AK 配额 | 浏览器端 AK 配额 |
| 结果差异 | E25（服务端 POI 集） | E36（SDK POI 集） |

> 双通道 POI 数据源存在差异（REST place v2 与 GL LocalSearch 返回集不同，住宅小区类差异最明显），
> 导致分数与斑块有波动。**这是数据源差异而非算法差异**，正式演示建议固定使用服务端通道，
> 并在报告中注明口径。

## 4. 结论

1. **系统输出与实际相符**：样例 A（新校区）被正确评为 E 级、识别出覆盖 100% 居住权重的重度灰色区域，
   与该片区"配套尚未建成"的实际一致；样例 B（老城核心）被评为 B 级、覆盖率 100%，区分度明确；
2. **人群差异化有实际意义**：老年人视角下样例 A 从"勉强可达"变为"完全不可达"，说明同一社区对不同人群的
   体检结论不同，规划应以最弱势人群的口径兜底；
3. **补点建议可执行**：系统给出药店补点落点与量化收益，可直接作为片区配套规划讨论的输入；
4. **主要误差来源**：①步行时间为"距离/速度×绕行系数"估算，未逐条计入红绿灯等待；
   ②等时圈外圈（>18 分钟）为线性外推趋势区；③人口代理为住宅小区 POI 密度；
   ④双通道 POI 数据源差异见 §3.4；⑤国标清单阈值为通行口径取整，非规范原文距离。
