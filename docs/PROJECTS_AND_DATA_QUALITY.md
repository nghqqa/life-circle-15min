# 本地项目与数据完整性

本批实现路线图第 1、2、6 项：设施检索完整性、项目保存恢复、报告版本与来源记录。方案 A／B 比较、CSV／GeoJSON 和地图报告增强属于后续工作。

## 保存与继续规划

1. 完成体检后，侧栏“本地项目”自动创建一个项目。重新体检会创建新项目，不覆盖上一次分析。
2. “采纳”“跳过”“撤销”会自动保存当前项目。刷新后自动打开最近保存的项目。
3. 修改名称后点“保存”；需要保留另一份操作状态时点“另存为”。从列表选择项目后点“打开”。
4. “导出项目”生成完整 JSON 快照，可换浏览器后导入。导入创建独立副本，不覆盖已有项目。
5. 页面底部原有“导出 JSON”仍提供报告摘要，包含本次新增的来源与完整性字段；摘要缺少完整网格和工作台数据，不能用于恢复。

项目记录参数、时间场、等时线、设施、评分、盲区、原始推荐以及已采纳和已跳过的完整选择。导入时恢复数值数组，避免刷新后无法继续计算。项目不保存地图 AK、网关配置或模型密钥。

## 数据完整性口径

所有关键词按顺序处理，每个关键词最多 3 页、每页 20 条。浏览器追加页之间保留 450ms 间隔；服务端继续使用限流桶。不会为了取全结果无限分页。

| 状态 | 含义 |
| --- | --- |
| 已取完 | 可信上游总数表明本次关键词结果已取尽；不代表现实设施普查 |
| 达到上限 | 已达到 3 页预算，仍有未取结果 |
| 部分结果 | 后续页失败、条目无有效坐标、总数变化或分页异常；保留已有有效数据 |
| 总量未知 | 上游没有提供可信总数，无法证明结果完整 |
| 检索失败 | 首次请求失败，没有可靠的该关键词结果 |
| 未执行 | 前序请求触发配额保护，停止后续关键词 |

报告显示“去重后已取数量 / 上游原始总数”。跨页重复 POI 会去重，因此两个数字可能不同。一个类别有多个关键词时，任何一个详细检索不完整都会使该类别不可可靠判定；保留其已取设施供参考，不据此作缺失或补建判断。

任一核心类别不完整时，三件套完整覆盖率为“无法评估”。住宅样本不完整时，不把部分住宅作为完整人口分母，暂停基于该人口代理的规划。已知完整且返回 0 条的检索，是有效的零结果。

配额或限流错误会中止该轮后续 POI 请求；前端也跳过可选过街扫描。服务端批量分析保留已有任务预算，分页请求也计入预算，因此数据密集区域可能更早停止。旧扩展 provider 若只返回 POI 数组，继续兼容估算，但明确标注总量未知。

## 来源与版本

每份新报告保存报告编号、生成时间、应用／算法／规则版本、配置指纹、坐标系（BD-09）、人口代理口径与数据通道。

POI 查询分别记录采集时间、页数、总数、状态和是否全部来自缓存。多页采集时间取最早页，缓存命中保留原采集时间。路线缓存的原始采集时间尚未记录，报告会明确提示。

规则或算法与当前版本不一致、或者缺少版本记录的历史项目，可以查看和导出；规划页要求重新体检，避免用当前规则悄悄改写历史结论。版本字段是复现记录，不是对导入文件真实性的数字签名。

## 本地存储的范围与限制

- 数据仅存在当前浏览器、当前站点；清理站点数据或更换访问地址后不会自动同步。请定期导出项目备份。
- 最多保存 20 个项目，本地项目库采用保守的 4 MiB UTF-16 预算；实际可保存数量还取决于项目大小和浏览器共享存储空间。
- 单个导入／导出项目上限为 8 MiB。可导出的文件不一定能放入剩余本地空间。
- 存储空间不足或浏览器拒绝保存时，页面明确提示未保存；旧项目保持不变，当前内存结果仍可导出。
- 旧报告摘要、未知格式版本、损坏数据和不一致的网格参数会被拒绝。损坏的本地库不会被自动覆盖；可在另一个浏览器导入已导出的完整项目备份。
- 当前不提供多人同步、服务器备份、跨标签页协作或批量任务断点恢复。

## 离线验证

```sh
npm ci
npm run typecheck
npm test
npm run build
npx playwright install chromium --only-shell
npm run test:browser
```

浏览器测试使用专用本地静态服务，不加载 `.env`，默认仅提供合成数据，并拦截外网请求。受控代理测试由测试代码返回分页和配额响应，不请求百度服务；测试并发为 1。

覆盖内容包括分页截断、总数未知、部分失败、缓存时间、配额中止、住宅分母缺失、完整项目恢复、采纳与跳过后撤销、存储失败、恶意／损坏文件、历史规则保护和报告来源一致性。
